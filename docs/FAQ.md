# 常见问题与细节

## 前置要求

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | ≥ 22（推荐 22 LTS） | 构建与测试，`.nvmrc` 已提供 |
| npm | ≥ 10 | 随 Node 附带 |
| DeepSeek API Key | — | [创建地址](https://platform.deepseek.com/api_keys)，账号需有余额 |
| 浏览器 | 近两年的 Chrome / Edge / Safari | 需要 `fetch` + `ReadableStream` |

项目**没有运行时依赖**，`dependencies` 为空。

## 安装与验证

```bash
git clone https://github.com/seeyouyousee/sift.git
cd sift
npm ci
npm run dev        # http://127.0.0.1:5173
```

验证安装：

```bash
npm run build      # 类型检查 + 构建，产出 dist/
npm test           # 133 个单元测试
npm run e2e        # 31 项端到端（离线，不花钱）
```

搜索后状态栏应出现类似：

```
48 条结果 · 第 1–10 条 · 共 5 页 · 759ms · 本次 ¥0.005 · 合并重复 2
```

## 配置项

全部集中在 `src/config.ts`：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `brand` | `Sift` | 站点名，改成你自己的 |
| `searchEndpoint` / `fetchEndpoint` | DeepSeek 官方 | 也可在设置里临时覆盖（指向自己的代理） |
| `maxCount` | `50` | 单次取回条数，也是分页上限 |
| `comparePresets` / `compareCount` | 知乎/GitHub/微博/B站 · 10 | 对比模式的栏目 |
| `qps` | `5` | 令牌桶速率 |
| `cacheTtlMs` / `cacheMaxEntries` | 10 分钟 / 60 条 | 客户端缓存 |
| `dedupeBlocklist` | `[]` | 直接丢弃的域名（默认空：屏蔽是观点） |
| `answerModel` / `answerMaxSources` / `answerMaxTokens` | `deepseek-chat` · 8 · 600 | AI 摘要 |

## 成本与限速

| 约束 | 数字 | 应对 |
| --- | --- | --- |
| 限速 | 5 请求/秒，**按账号** | 令牌桶排队、同 query 合并、缓存 |
| 结果上限 | 单次最多 50 条 | 一次取满，前端分页 |
| 计费 | ¥5 / 1000 次成功请求 | 只缓存非空结果；失败/无结果不计费 |
| AI 摘要 | 每次约 ¥0.01 | 可关闭 |

## 常见问题

**提示「API Key 无效」？**
Key 过期/被删，或粘贴时带了空格。⚙ →「删除本机 API Key」重填。

**AI 摘要一直转圈或 429？**
摘要是一次额外的模型调用，踩到 5 次/秒限速。等两秒重试，或在设置里关掉 AI 摘要。

**「阅读正文」提示抓不到？**
目标站点从服务端抓不到（被墙、需登录、反爬、纯 JS 渲染）。行内会给出原因和「在新标签打开原链接」。

**为什么不如百度准？**
索引规模差几个数量级，且该接口的排序目标是「适合模型摘录」而非「最想点开」。能改善的（去重、AI 摘要）已经做了，见[已知限制](#已知限制)。

**会收集数据吗？**
不会。唯一出网请求是浏览器 → `api.deepseek.com`。无埋点、无后端、无日志。

**能多人共用一个 key 吗？**
不建议。5 QPS 是账号级的，会互相排队。共享请用 `server/proxy.mjs`。

**可以商用吗？**
MIT 允许。但备案、生成式 AI 标识、品牌红线得自己处理。

## 已知限制

- 只有 5 页（50 条），做不了无限翻页——接口上限。
- 对比模式一次 4 个请求，冷门词在 5 QPS 下排队约 0.8s。
- 没有搜索建议接口，联想只基于本地历史。
- 单一 provider，DeepSeek 侧故障时没有兜底引擎。
- 共享 key 模式（`server/proxy.mjs` 的方案 C）没有身份体系，防刷只能靠网关。

## 试过但删掉的东西

三个「让检索更聪明」的尝试全部被删除，因为测不出收益：

| 尝试 | 结果 |
| --- | --- |
| 本地重排（相关度+权威+时效，同域降权） | 唯一域 8.2→8.3，中位分 1.86→1.84 |
| 下载意图的 `site:` 限定召回 | 能找出仓库，但要人工分辨官方/量化版 |
| 意图规划 + 多路 RRF | 12 题 A/B 盲评 5:7 落败 |

共同点：它们都在「让检索更聪明」；真正让体验变好的是「把结果写成一段带引用的答案」。
所以重排、planner、官方源那一套都不在仓库里了。详见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 合规

1. **品牌**：开放平台协议 5.2 禁止用「DeepSeek」商标、名称、域名、LOGO 做站点品牌，也禁止暗示官方合作。
2. **生成内容标识**：`summary` 是模型生成的，公开展示需加标识（卡片上的「AI 摘要」徽标就是）。
3. **备案与内容安全**：境内公网运营需 ICP 备案，并承担内容审核义务。
